# Documentation sync

Requires the `toolu` plugin and native binary. Inspect the committed diff with `toolu docs inspect` from the repository being pushed (or pass `--repo PATH`, and `--branch NAME` when needed). Establish the changed behavior from implementation, tests and affected documentation; do not claim a historical audit. For a detached checkout, pass `--branch NAME` naming an existing local branch; inspection still reviews the committed `HEAD` diff. The base is the branch `origin/HEAD` names, else `master` or `main`, locally or on `origin`; if none is found, run `git remote set-head origin <default-branch>` (exporting `DOCS_SYNC_BASE` works only before the host starts). A checked-out branch must match `NAME`. Coordinate one documentation writer at a time. Check out and review the branch being pushed. The push gate supports one static, plain `git push` with an explicit remote and one source resolving to `HEAD` (a local branch resolving to `HEAD` or `HEAD:<branch>`), plus ordinary no-value flags. Use `git push <remote> HEAD:<branch>` when a push is rejected. Implicit pushes, multiple refs or commands, `--all`, `--mirror`, `--tags`, wrapped commands, dynamic `-C`, and `--git-dir`, `--work-tree`, or `-c` overrides are rejected according to the effective gate mode, as are dynamic git subcommands, plumbing pushes and Git aliases that may push. A lone push whose commits are already in the base passes. Static `git -C PATH` is supported; with `push.followTags=true`, add `--no-follow-tags`.

Discover configured profiles and check each host, model and effort for actual availability and capabilities. Use only ready tuples. Follow [routing](references/routing.md) to supply evidence and ask `toolu docs route --candidates FILE --evidence FILE`. Missing credentials, no suitable route, invalid output or a readiness change is an explicit failure: start no worker, or repeat readiness and routing after a change. Never invent a model, inherit an unspecified tuple, or silently substitute one.

Launch a **separate editing sub-agent** with the selected host/model/effort tuple. Use the native subagent API only if it honors the entire tuple; otherwise use the Herdr workflow in [routing](references/routing.md). A same-thread role is not a worker. Give it [worker instructions](references/worker.md), inspect identity and actual route, and bound the wait. On timeout, blocked state, launch failure or incomplete result, inspect and report the failure; do not stamp a review, blindly resubmit or recursively delegate.

Review its edits and findings. The parent commits authorized changes, re-runs `toolu docs inspect`, and asks the **same worker** to review the final committed diff and return a fresh report. Resolve findings and repeat if the diff changes. With tracked files clean, write the validated report using `toolu docs write-state --report FILE` (plus the same repo/branch overrides); every host's gate reads it. Failures remain failures; never create a SHA-only attestation. The worker does not commit or push.
