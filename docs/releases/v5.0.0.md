# toolu v5.0.0

Released: 2026-08-26

## Highlights

toolu's gates stop being walls and become questions. The discipline is intact;
what changed is how it reaches you.

- **Every gate has a mode.** `block` | `ask` | `advise` | `off`, per gate, with
  `gates.preset` (`strict` | `balanced` | `relaxed`) to set them all at once.
  The default is **balanced**.
- **`git push` asks instead of blocking.** An unreviewed push now prompts, and
  a yes is remembered for that exact diff — a new commit asks again, a retry
  does not. Refusing records nothing.
- **The quality gate stops shipping, not working.** While it is red it denies
  `git commit` and `git push`; reading, searching, editing, and running
  commands are untouched. It used to deny nearly every tool call.
- **git and gh are no longer on the denylist.** Force pushes and pushes to the
  base branch are your call at the prompt. What remains on the denylist
  (`node -e`, `bun -e`, `cargo test`) asks rather than denies.
- **`.claude/tmp` cleans itself.** SessionStart reclaims state for branches that
  are gone or merged, anything past a TTL, spent quality-gate records, and
  telemetry beyond its retention window — never the branch you are on, and
  never a failing gate about files that still exist.
- **Host permissions settle themselves once.** The first session in a repo
  writes `Bash(*)`, `Edit`, `Write` into `.claude/settings.local.json` and
  records a sentinel, so a rule you delete stays deleted.

## Upgrade notes

**Behaviour changes by default.** The first session after upgrading prints a
one-time notice. To keep exactly what you had:

```json
{ "version": 1, "gates": { "preset": "strict" } }
```

Or relax one gate at a time with `gates.<name>.mode`. Full reference:
[`docs/config.md`](../config.md) and
[`plugins/toolu/hooks/docs/gates.md`](../../plugins/toolu/hooks/docs/gates.md).

Two things to know before you rely on a mode:

- **`permissions.deny` overrides a hook's `ask`.** A command denied in your
  Claude Code settings is denied outright and toolu never prompts about it.
  `permissions.allow` does not have that power. `settings/permissions.fragment.json`
  dropped its `git push --force` and `node -e` deny rules for exactly this
  reason — they would have silently outranked the gate modes.
- **The permission auto-write is a broad grant.** `Bash(*)` means the host
  stops prompting for shell commands, destructive ones included. Set
  `permissions.autoAllow: false` if that is not the trade you want.

On Codex, `ask` degrades to `advise` — the host cannot prompt, and a gate that
silently did nothing would be worse than one that speaks.

`protected-files` and `mcp-blocker` are unchanged: they deny at every preset.

## Included changes since v4.6.0

- `toolu`: per-gate delivery modes (`block`/`ask`/`advise`/`off`) with presets, resolved by the new `hooks/lib/gate-mode.sh`.
- `toolu`: the PreToolUse dispatcher holds an `ask` so a later module can still deny, and appends advisories to the prompt's reason.
- `toolu`: push-review asks by default and honours diff-keyed waivers (`hooks/lib/push-waiver.sh` + `hooks/post-tools/modules/push-waiver.sh`), promoted only after a push that actually succeeded.
- `toolu`: quality gate narrowed to `git commit` / `git push`, using the new `is_git_commit` alongside `is_git_push`.
- `toolu`: SessionStart state sweeper (`hooks/lib/state-sweeper.sh`) with `gates.sweep`, `gates.stateTtlHours`, `gates.telemetryRetentionDays`.
- `toolu`: one-time per-repo permission allowlist (`hooks/lib/permissions.sh`), sentinel kept out of the committed config.
- `toolu`: `git push` rules removed from `settings/bash-denylist.txt`; `settings/permissions.fragment.json` deny block reduced to catastrophic commands only.
- `toolu`: commit-gate, plan-ledger, docs-sync, and agent-tier re-plumbed onto the shared resolver, with their legacy config keys still honoured.
