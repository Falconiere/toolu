# Doctor and `plugins remove` handle retired marketplace plugins — Plan

**Date:** 2026-10-24   **Status:** Approved   **Spec:** docs/toolu/specs/2026-10-24-doctor-retired-plugins-design.md   **Topic:** retired toolu plugins warn in doctor and `toolu plugins remove` removes them (#615)

## Evidence and approach
Inspected: `crates/toolu/src/doctor/skew_check.rs` (assesses every inventory root), `crates/core/runtime/src/skew.rs` (unreadable manifest is a mismatch with update advice), `crates/plugins/src/dispatch.rs` (`remove` validates names with `install_order`, 285 lines), `crates/plugins/src/catalog.rs` (embeds `.claude-plugin/marketplace.json`), `crates/plugins/src/catalog/order.rs` (unknown-plugin message), `crates/xtask/src/layers.rs` (the hub may not depend on the plugins crate), `Roots::plugin_uninstall_command` (Muse's native remove), and the CLI harnesses `crates/cli/tests/doctor_report.rs` and `plugins_hosts.rs` (stub host CLIs at the process boundary). Live: `claude plugin uninstall context7@toolu` (2.1.310) and `codex plugin remove context7@toolu` (0.164.0) remove a retired 7.11.0 plugin in isolated homes.

Approach as decided in the spec: move the built-in catalog text into `toolu_runtime::catalog`; doctor sets retired plugins aside before `skew::assess` and hints the inspected host's removal command; `remove` accepts well-formed non-catalog names on Claude Code, Codex and Cursor through `order::removable`.

## Workstream summary
shared catalog → remove gate → doctor retired rule → doctor end-to-end → docs → live evidence → gate. Each behavior step (s1–s4) starts with its new test failing on the unchanged code, recorded as red evidence, then turns green.
