# Jev 1.14: images, Box answers and long context — Plan

**Date:** 2026-11-12   **Status:** Approved   **Spec:** docs/toolu/specs/2026-11-12-jev-1-14-images-design.md   **Topic:** Bring the jev plugin to the Jev 1.14 API contract

## Evidence and approach

- Live docs read on 2026-11-12: `docs.typesafe.ai/images.md`, `primitives/box.md`, `api/system-one.md`, `models.md`, `api/errors.md`, `changelog.md`.
- Inspected: `crates/core/jev/src/{lib,retry,reply,question}.rs`, `crates/jev/src/{cli,call,lib,present}.rs`, and the four crates that call the client. `toolu_http` caps only response bodies (`max_body_bytes`), so a request of up to 32 MiB is sent as is.
- Constraint: code-review uses `request_body` text as its replay key, so a request without images must keep its exact body.
- Approach: additive. New `Assets`, `Extras`, `Jev::ask_with` and `Answer::Box` in the client; two flags on every `toolu jev` verb; the opt-in headers are derived from the request. Images go base64 in the JSON body.
- Reused: the loopback TLS fixture of `toolu-http-test-support` through `crates/core/jev/tests/helpers/endpoint.rs` and `crates/jev/tests/helpers/harness.rs`.

## Workstream summary

Client (assets, headers, Box reply) → CLI flags and the consumers' match arms → skill, docs and generated CLI reference → full gate.
