# OpenCode native launcher compatibility — Plan

**Date:** 2026-10-06   **Status:** Approved   **Spec:** docs/toolu/specs/2026-10-06-opencode-native-launcher-design.md   **Topic:** Issue #461, native lifecycle launchers on OpenCode and repository checks

## Evidence and approach

The #412 launcher is generated by `crates/core/protocol/src/launcher.rs`; its command embeds a Bun fallback bundle, and Rust `cargo xtask check-hooks` already validates the native fields exactly. OpenCode's `bootstrap/entrypoint.ts` currently recognizes only the Bun generator and `spawn.ts` always runs a Bun bundle. Coverage discovery normalizes the bundle path, but its seeded `hostMechanism` is always `bun-bundle`. The pinned-host probe knowledge in comemory `6990a41a` gives the real OpenCode execution setup. The approved spec resolves the transition case: explicit missing `TOOLU_BIN` reaches the install message; no override keeps #412's Bun fallback.

## Workstream summary

Recognize and run native lifecycle entries, validate both launcher forms, retain coverage identity while tracking mechanism, prove delivery through the pinned host, then synchronize docs and run gates.

## Deviations

- The bootstrap step now includes `plugin/context-delivery.ts`: the initial plan listed only startup files, but this adapter independently builds prompt and compaction jobs from the same entries. It must forward the native command to keep both lifecycle events running.
- The launcher checker now validates the Windows command and timeout too. Two complete hooks generated by `cargo xtask print-hook` are pinned by a Rust test, so the TypeScript gate can run without Cargo and cannot silently drift from the Rust generator.
- The pinned OpenCode CI job does not install Rust. Three actual-host scenarios exercise the generated native launcher with a protocol-compatible executable, explicit missing `TOOLU_BIN`, and statusline's transitional Bun fallback. A third complete Rust-generated fixture is pinned for statusline. The native install `systemMessage` now reaches session context as well as the host log; Bun startup notices keep their existing log-only behavior.
- Pre-push review found that #412's Bun fallback runs the bundle without `--no-env-file`, unlike OpenCode's direct Bun path. Native subprocesses now receive a disposable `TOOLU_BUN` wrapper that adds the flag; a real generated-command test with a project `.env` verifies the value stays absent.
- Pre-push review also found that structural native recognition accepted an appended shell command. The runtime now compares the entire command to a packaged Rust golden, pinned by a Rust test and required by the npm inventory. A real hook-file mutation test verifies the edited command is reported.
- Real prompt and pre-compaction subprocess tests now use two more Rust-generated hook fixtures, pinned to the generator alongside the startup and enforcing fixtures.
