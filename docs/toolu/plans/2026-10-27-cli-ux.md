# toolu CLI look, progress and plugin update targets — Plan

**Date:** 2026-10-27   **Status:** Approved   **Spec:** docs/toolu/specs/2026-10-27-cli-ux-design.md   **Topic:** Clack-style output, progress and checkbox picker for `toolu plugins`, prompt-free multi-host `update` limited to toolu's plugins, `toolu status` table.

## Evidence and approach

- **Recalled:** comemory `627f8394` (the Claude update bug and its root cause), plus memory
  notes on the local gate (rustup `cargo` first, `TMPDIR=/private/tmp`, a plugin newer
  than the binary blocks tools) and on GitHub workflows being disabled (no CI and no
  babysit; the user merges).
- **Inspected:**
  - `crates/plugins/src/{lib,dispatch,report,step,prompt,host,verbs}.rs`,
    `host/{claude,codex,adapter,run}.rs`, `verbs/{install,update,remove,list}.rs`,
    `cursor{,/store,/change}.rs`, `tests/support_test.rs` (stub hosts, `muse_output`
    fixture replay);
  - `crates/core/runtime/src/{cli,env,lib}.rs`, `crates/cli/src/{output,dispatch}.rs`,
    `crates/toolu/src/status{,/gate,/repo}.rs`;
  - `tooling/conventions/guardrails/rust/rules.json` (only `toolu-cli::output` touches
    stdio), root `Cargo.toml` lints (`unsafe_code` forbid, `indexing_slicing` and
    `expect_used` deny), and guardrail rule 7 (every module with a function has a wired
    `tests/<module>_test.rs`).
- **Real data captured** (Claude 2.1.311), in `/private/tmp/cli-ux-capture/`:
  - `plugin list --json`: 30 `toolu@toolu` rows (29 project, 1 user), retired `context7`,
    `exa-search` and `jira`, and foreign `cloudflare`, `comemory`, `exa`,
    `rust-analyzer-lsp`, `ponytail`, `caveman`;
  - `update jev@toolu --json`: up_to_date;
  - `update cloudflare@toolu --json`: failed, not_found.
- **Approach:**
  - Fix the update targets at the root, in the shared Claude parser.
  - Add `toolu_runtime::term` and carry `Style` in `Ctx`.
  - Build rails, progress and the checkbox in `crates/plugins` over `/dev/tty` with `nix`
    termios.
  - Then the prompt-free update fan-out, the status table and the docs. The plain path is
    unchanged.
- **Check convention:** every check runs the whole crate (toolu-plugins is about 130
  fast tests), plus `-- --list | grep '<module path>::tests::'` for new modules, so an
  unwired test file cannot pass. Paths use the crate directory, because `Context` and
  `Driver` literals span many test files.

## Workstream summary

Claude parser and fixture → update targets (Claude, Codex, Muse, Cursor) → term style in
`Ctx` → rails reports → progress → key decoder and checkbox → host detection → prompt-free
update → status table → plain-output guard → docs → live terminal check → full gate.

## Verification

- **End to end:** `docs/toolu/evidence/2026-10-27-cli-ux-live.sh` runs `cargo build -p
  toolu-cli` and then calls `target/debug/toolu` by path, never the stale `toolu` on
  PATH. Interactive steps go through an `expect` script file
  (`docs/toolu/evidence/2026-10-27-cli-ux-live.exp`, `/usr/bin/expect`), which waits for
  the `◆` prompt before sending keys. Text assertions run with `NO_COLOR=1`; one Color
  run asserts `\x1b[` is present. It asserts:
  1. `script -q` capture of `plugins install --host claude --dry-run --no-input` (no
     picker, so the ledger's EOF stdin cannot cancel it): `┌  toolu plugins
     install`, `◇  claude`, a `└` footer, and the progress clear `\x1b[1A\r\x1b[2K` in the
     raw bytes.
  2. `plugins update --host claude --dry-run --json`: the step names equal the set of
     `@toolu` names from `claude plugin list --json`, deduplicated. None of `cloudflare`,
     `comemory`, `exa`, `rust-analyzer-lsp`, `ponytail` or `caveman` appears (exact
     `.steps[].name` match). `context7`, `exa-search` and `jira` are `skew` with
     `--host claude --yes` in the detail.
  3. One real `plugins update jev --host claude` under `script`: bar `1/1`, then a `jev`
     row with `current at` or `updated` in the report.
  4. `plugins install --dry-run` under `script`, fed `\x1b[B`, space, `\r` and then `\r`:
     `◆`, `◼`/`◻` and the collapsed `◇  Which hosts…` line.
  5. A `q` cancel: `cancelled` with exit 1, and `stty -g` before and after equal inside the
     same pty.
  6. `status` under `script`: `┌  toolu status` and `│  branch`; piped: no `\x1b`.
- **Failure and boundary cases:** per step: prepare failure, empty listings, `--scope` off
  Claude, unknown keys, cancel paths, `NO_COLOR`, `TERM=dumb`, not a repository.
- **Docs:** the `docs` step. Its `docs_test` is wired from `lib.rs` as `mod docs`, so its
  tests list as `docs::<fn>`. The test collapses whitespace (`split_whitespace` joined by
  one space) before asserting, and its negative assertions on the stale phrases ("Cursor
  is never probed", "The prompts are numbered lines", "`remove` and `update` print") are
  first run red against today's `installer.md`.
- **Environment:** host-run checks stay on the package targets that are green at
  baseline: toolu-plugins 131, toolu-hub 128, `toolu-cli --bin toolu` and the named
  integration tests. The whole gate runs in the clean `toolu-deploy-gate` container
  (`colima-toolu-gate` profile), because Homebrew toolu and the live engine make some
  host tests red (memory: local-gate-env-quirks).
- **Delivery:**
  1. Scoped Conventional Commits: `fix(plugins)` for the update targets, `feat(cli)` for
     term and status, `feat(plugins)` for rails, progress, picker and fan-out, `docs` for
     docs.
  2. `docs/toolu` files are added with `git add -f`, including the plan with its
     `Status: Approved` stamp. The `gate` step runs only after every commit, because
     `deploy-gate` refuses a dirty worktree. `git fetch origin main` runs first, so
     `refs/remotes/origin/main` is known.
  3. `PLAN_LEDGER_STEP_TIMEOUT=7200 toolu ledger run docs/toolu/plans/2026-10-27-cli-ux.md
     --verify`: the container gate can pass the 1800 s default on a cold volume. Then
     `toolu-review:review` (push-review v2), then `toolu ledger verdict status` reporting
     `overall: ready`.
  4. Push `cli-ux` and open a PR to `main` titled `feat(plugins): clack-style installer UI,
     progress, and prompt-free update of toolu plugins only`. Its body carries the
     `update --json` compat note (spec Non-Goal 1).
  5. The user waived babysit (GitHub workflows are disabled), so the PR is the final
     delivery artifact.

## Deviations

- **Live-check scripts stay untracked.** The `final-removal` gate forbids tracked
  shell files, so `docs/toolu/evidence/2026-10-27-cli-ux-live.{sh,exp}` live in
  the gitignored `docs/toolu/` only. The `live-check` step still runs them locally.
- **Pre-push review fixes:**
  - A host whose listing fails is noted with the cause; the nothing-to-update
    error names unreadable hosts.
  - Each host is listed once: `verbs::update::run` takes the listing the fan-out
    already read.
  - Claude without `plugin update --json` gets a version hint.
  - Spinner-only lines are capped at 64 columns.
  - Cursor detection reads `~/.cursor`, not `TOOLU_CONFIG_DIR`.
  - The `update` help text was reworded.
  - New tests: the remaining `update_step` branches, progress wiring through real
    verb runs, and a real-pty run of the built binary
    (`crates/cli/tests/terminal_output.rs`, which adds the `nix` dev-dependency
    with `term`).
- **Simplifications:** `Progress::open` lost its `json` flag, `intro_shown`
  became `progress.is_some()`, `Driver::offered()` and `targets()` are shared, and
  the Codex test stub moved to `tests/support_test.rs`.
