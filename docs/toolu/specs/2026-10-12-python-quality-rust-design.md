# python-quality as a Rust rule crate — Design

**Date:** 2026-10-12   **Status:** Approved   **Author:** epic worker (#427)   **Topic:** port python-quality's post-edit rules into `toolu` (epic #402)

## Problem

python-quality's Python checks run as a Bun bundle (`plugins/python-quality/hooks/dist/post-tool-use.js`) that a Bun SessionStart hook copies into `post-tools.d`. Epic #402 removes Bun from hooks. The rules must run compiled into `toolu`, enabled by a manifest, through the shared quality runner of #459, with the same messages and gate entries. #426 (ts-quality, PR 515) did the same for TypeScript; this port reuses its engine changes and shares its registration code instead of copying it.

## Non-Goals

1. Switching toolu's own `PreToolUse`/`PostToolUse` `hooks.json` entries to the native dispatcher (#425), or the OpenCode adapter's in-process dispatch (#440).
2. Porting rust-quality (#428).
3. New rules, changed messages, ruff or a type checker. Behaviour is the golden corpus (`fixtures/quality/python.json`, 96 cases, `python-golden.json`).
4. Removing the Bun ESM bridge from the engine (#440).

## Architecture

**Crate.** `crates/python-quality` (`toolu-python-quality`) depends on `toolu-engine`, `toolu-runtime`, `toolu-state`, `toolu-protocol`, `regex`, `clap`. One type, `PythonQuality`, implements `toolu_runtime::registry::rule::Rule` (spec `python-quality@toolu`, name `python-quality`, event `ToolPost`, `applies` only to an edited `.py` path) and `toolu_engine::quality::QualityRule` (language `python`, extension `py`, source `python-quality-hook`, reason `Post-edit Python quality violation(s) detected`, linked worktrees not skipped, `project_enabled` = `detect_python` and `python3` on `PATH`). `Rule::run`/`run_warning` call `run_quality_event` with `[&PythonQuality]`, as ts-quality does. The hub adds it to `toolu_hub::tool_hook::RULES` and re-exports the crate.

**Rules.** A line-for-line port of `plugins/python-quality/hooks/src/rules/`, in `check.ts` order: file too long (`count_python_code_lines`'s count, taken from the text already read), test layout (two messages), suppression, function too long, no-mocks; then the docs advisory, shown only when nothing blocks. Same regexes (POSIX `[[:space:]]` is `[ \t\n\v\f\r]`, `.` matches `\r`; TypeScript's `(?![A-Za-z0-9_])` after `pytest|unittest` becomes an explicit next-character check, as Rust's `regex` has no lookahead), same `head` caps (5 for suppression and mocks, 3 for docs) and message text. Limits from `lang.python` (`maxFileLines`, `maxFnLines`, `noMocks`) via `quality_threshold`/`quality_flag`, resolved once per checked file. A file is read as bytes and decoded lossily, as ts-quality does.

**No-mocks scan.** Per file, not batched (Jev 1.0): `ast_rules_inline` stays empty and `check` calls `toolu_engine::quality::scan_inline(&[file], RULES, ctx)` only for a `test_*.py`/`*_test.py` file with `noMocks` on — exactly when TypeScript spawned ast-grep, so a non-test edit spawns no ast-grep. `Missing` skips the rule; an empty-output or parse/exit failure adds the same "ast-grep failed while scanning" violation.

**Shared registration (new, `toolu_engine::quality::plugin`).** ts-quality's `register.rs` (manifest + bridge `.sh` + prune + startup report + upgrade message) and `hooks.rs` (`check_toolu`) move into the engine as `QualityPlugin`, a `const` description of one quality plugin (plugin name, spec, rule name, path glob for the bridge, guard variable, skipped-language label). `QualityPlugin::register(&Env, Host) -> Outcome`, `check_toolu(&Env) -> Outcome` and `bridge_script(&Path) -> String` keep ts-quality's bytes and behaviour (its unit and conformance tests stay green unchanged); the atomic write uses `toolu_runtime::atomic::write_atomic` instead of `tempfile`. ts-quality and python-quality each declare one `QualityPlugin` and re-export the functions, so neither crate copies the other (jscpd: 0 clones in `crates/**/src`). `crates/cli/src/hook/plugins.rs` routes both plugins' `register`, `check-toolu` and `post-tools` through one function over a `[&QualityPlugin]` table from the hub instead of a second copy of `ts_quality_hook`.

**Bridge until #425.** python-quality's bridge is ts-quality's with `*.py*` for the path test, guard `TOOLU_PYTHON_QUALITY_NATIVE` and `python-quality hook post-tools`. `toolu python-quality hook post-tools` runs the engine dispatch with no built-ins and only `python-quality@toolu` selected (`plugin_tool_hook`, `split_by_caller`, from #426). The native dispatcher shadows the `.sh` with the usable manifest, so the rule runs once.

**Plugin.** `hooks.json` keeps two SessionStart entries, generated by `cargo xtask print-hook python-quality SessionStart register` and `… check-toolu`. `hooks/src` and `hooks/dist` are deleted; the plugin ships `hooks.json`, two `plugin.json` and its README.

**Namespace.** `toolu python-quality` becomes a `Guide` (no verbs): what it checks, when, its `lang.python` limits, and `toolu doctor`. `planned` goes (exempt from `cli-compat`).

**Tests.** The TypeScript suites move to `tools/toolu-conformance/src/python-quality/` like #426's: the golden corpus on two legs (native `toolu hook post-tools` via the `TOOLU_IMPL` seam, and Bun `post-tools.js` with the bridge), register and read-failure. `nativeRegisterArgv` covers python-quality. Focused Rust integration tests in `crates/cli/tests/python_quality_hook.rs`; unit tests per module. Once #428 also made rust-quality native, no quality plugin ships a Bun bundle: `crates/core/engine/tests/quality_bridge.rs` (a quality bundle run by the TypeScript dispatcher and by the engine's `.js` bridge) and its `dispatch-cli.ts` are deleted, since `fixtures/dispatch/cases.json` already holds both implementations to the same `.js` module output, and the OpenCode startup-failure checks (`startupFailure`, `hooks.test.ts`) use a hand-written python-quality register command, which the bootstrap refuses.

## Interfaces / Schema

- `toolu_engine::quality::plugin::QualityPlugin { plugin, spec, name, path_glob, guard, language_label }` (all `&'static str`) with `register(&self, &Env, Host) -> Outcome`, `check_toolu(&self, &Env) -> Outcome`, `bridge_script(&self, &Path) -> String`.
- `toolu_python_quality::{PLUGIN, SPEC, PYTHON_QUALITY: &dyn Rule, QUALITY_PLUGIN: QualityPlugin, register, check_toolu, command, run}`; ts-quality keeps its public names, now delegating.
- Hook verbs (fast path): `toolu python-quality hook register|check-toolu --event SessionStart --plugin-root <dir>`, `toolu python-quality hook post-tools --event PostToolUse`.
- Registry files: `python-quality@toolu__python-quality.json` (`{"version":1,"spec":"python-quality@toolu","name":"python-quality","event":"tool/post","matcher":"*"}`) and `python-quality@toolu__python-quality.sh`.
- Gate entries (`source: python-quality-hook`) and telemetry: unchanged.

## Failure modes and edge cases

- **Unreadable file:** error `Cannot read <path> for Python quality checks: <detail>` (gate failing), as today.
- **Not a Python project / no `python3` on PATH / removed or moved file:** rule silent; a removed or moved file clears its source entry (shared runner).
- **ast-grep missing:** no-mocks skipped; **empty output, crash, unparsable output:** one "ast-grep failed while scanning" violation.
- **Non-`.py` edit:** `applies` is false; no git, ast-grep or python3 lookup from this rule.
- **Plugin uninstalled:** the manifest is gated off by installed-plugin gating; the Bun prune removes the stale `.sh`.
- **Bridge binary moved:** falls back to a native `toolu` on `PATH`; absent, one stderr line and exit 1 (the dispatcher reports it).
- **Register write failure:** a `systemMessage` advisory, exit 0.
- **Concurrent sessions:** atomic rename per file; identical content is not rewritten.

## Acceptance criteria

- **AC-1:** Every case of `fixtures/quality/python.json` (Claude Code and Codex) replayed against the native `toolu hook post-tools` with the manifest registered gives the stdout, stderr, exit code and state of `python-golden.json` (same normalisation and deviation handling as the TypeScript harness), except that the linked-worktree case records its entry in the worktree's own gate file (the #459 runner's AC-3) with identical output and nothing in the main project's state, which `worktree-gate.test.ts` checks; the `chmod 000` file is reported as `Cannot read … for Python quality checks`. The post-tool corpus still passes under `bun run test:conformance`.
- **AC-2:** With python-quality not installed (or no manifest), a Python edit with a violation produces no python-quality output and no gate entry.
- **AC-3:** An edit to a `.ts` or `.md` file with the manifest present spawns no ast-grep or python3 lookup from python-quality and writes no gate entry; the hook bench registers python-quality natively and reports `toolu/post-tools` on its README edit.
- **AC-4:** Through the Bun `post-tools.js` with the registered bridge, every golden case gives the golden output and gate entry.
- **AC-5:** On SessionStart after an upgrade, `python-quality@toolu__python-quality.js` is removed and the `.json` and `.sh` are written with an upgrade `systemMessage`; a second run leaves both byte- and mtime-identical and prints nothing; a violating `.py` edit after that register still reports and records its gate entry.
- **AC-6:** `plugins/python-quality/hooks/src` and `hooks/dist` are gone; the plugin has `hooks.json`, two `plugin.json`, README, and neither the README nor a `hooks.json` POSIX `command` names `scripts/`, `hooks/dist/`, a Bun bundle or `bun` (the generated `commandWindows` keeps the launcher's Bun chain and install hint until Windows has a binary, as `docs/install.md` states); `cargo xtask check-hooks` and `check-markdown-cli` pass; `toolu python-quality --help` and `toolu commands --json` show the guide with no verb, and `docs/cli/python-quality.md` matches it.
- **AC-7:** ts-quality's register, bridge and check-toolu behaviour is unchanged after the extraction: its Rust unit tests, `crates/cli/tests/ts_quality_hook.rs` and `tools/toolu-conformance/src/ts-quality` pass.
- **AC-8:** `cargo xtask gate` passes with no exemption.
- **AC-9:** On OpenCode, a selected python-quality registered by the built `toolu` makes the adapter's post-tool dispatch report a violation and a gate entry for a violating `.py` write, and nothing for an unselected plugin; the bootstrap verifies the `native-registry` record.
- **AC-10:** With python-quality's manifest registered in a real config dir, `toolu doctor --json` reports no `registry` finding for it.
- **AC-11:** `toolu python-quality hook check-toolu` on Codex with python-quality installed and `toolu@toolu` missing from `codex plugin list --json` prints the core-missing `additionalContext` notice (`WARN: this plugin requires the toolu core. …`) and exits 0; with the core installed, or on Claude Code, it prints nothing.

- **Rebase over #428 (resolved):** #428 (PR 518) merged first with the same shared `QualityPlugin` and `ManifestRule`. main's module is the base; this branch adds python-quality to `QUALITY_PLUGINS` and `RULES` beside ts-quality and rust-quality, and keeps its later changes to that module (`replace_atomic` errors, temp-residue prune). With no Bun quality bundle left, the bundle-based bridge and startup-failure tests were reworked as the Tests paragraph says (Jev 0.61 for deleting `quality_bridge.rs`).
- **Issue text vs design (decided, non-blocking):** the issue asks for a plain-`sh` manifest writer; like #426 and #429, registration runs through the native launcher, so the plugin still needs no binary of its own (the issue's intent), and roots come from `toolu_runtime::host::roots::Roots`, which is already parity-tested against #414's `fixtures/host/root.json`; a separate shell writer would be a second copy to keep in parity. The `.sh` is the Bun-dispatch bridge only.
- **Linked-worktree gate file (decided in execution, non-blocking):** the golden case "flow: a file in a linked worktree is checked" was captured with the gate entry in the hook's project root; the shared runner (#459, approved AC-3) records it in the linked worktree's own state, as `docs/opencode.md` already documents. Kept as a named, tested deviation (Jev 1.0) rather than changing the shared runner that rust-quality also uses.
