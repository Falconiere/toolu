# OpenCode native launcher compatibility — Design

**Date:** 2026-10-06  **Status:** Approved  **Author:** Codex  **Topic:** Run generated native lifecycle hooks on OpenCode and keep repository checks stable.

## Problem

OpenCode currently starts only Bun launcher entries from `hooks.json`. A plugin switched to the #412 native launcher would lose SessionStart, prompt, and compaction context. The coverage inventory must retain the entry's identity while recording its new host mechanism.

## Non-Goals

1. Change the OpenCode pre-tool or post-tool adapter; #437 owns its Rust migration.
2. Change #412's binary resolution or Bun fallback behavior.
3. Switch a committed plugin entry to native; later port issues own those switches.

## Architecture

`bootstrap/entrypoint.ts` recognizes the generated Bun launcher exactly, and recognizes a native entry by the #412 protocol marker, fallback bundle path, and matching plugin, event, entry, and plugin-root invocation. It returns the command to run with the entry identity. `spawn.ts` runs Bun entries as before and native entries through `/bin/sh -c <hooks.json command>` under the same cwd, environment, stdin, timeout, cancellation, output bound, report ledger, and result parser. Unknown commands remain named startup failures.

`check:hooks-json` checks the native POSIX command against the Rust launcher's committed golden commands with controlled plugin, event, and entry substitutions, and checks Bun commands against `@toolu/core/launcher` as before. `cargo xtask check-hooks` remains the exact generator check for native `command`, `commandWindows`, and `timeout`. Together they reject hand edits without making the TypeScript gate require Cargo or duplicating the large shell generator in the OpenCode runtime.

Coverage discovery normalizes Bun and native commands to the same `hooks/dist/<entry>.js` identity, so a switch retains the inventory ID. It derives `hostMechanism: "native"` from a native hook command and compares that field during inventory validation; seeding a switched row updates the field and matrix without changing its ID.

## Interfaces / Schema

- `StartupEntry`: `{ name, bundle, command?: string }`, where `command` is the generated native POSIX shell command and absent for Bun.
- `SpawnRequest`: the existing fields plus an optional native command; when present the child argv is `/bin/sh -c <command>`.
- `Discovered`: the existing fields plus `hostMechanism: "bun-bundle" | "native"` for `hooks.json` rows; non-hook rows remain `"bun-bundle"`.
- No new user configuration or host protocol field.

## Failure modes and edge cases

- Unsupported hook types, hand-written commands, mismatched plugin/event/entry, malformed JSON, and absent fallback bundle produce a named startup failure. The TypeScript launcher gate also catches a native command with its protocol marker removed.
- Native shell startup failures, nonzero exits, invalid JSON output, timeouts, oversized output, and cancellation use the existing failure and cleanup path.
- With `TOOLU_BIN` explicitly set to a nonexistent path, #412 emits a `systemMessage` naming both install commands and exits 0; OpenCode treats it as session context and continues. With no override and Bun available, #412 retains its Bun fallback.
- Native `commandWindows` is checked by `cargo xtask check-hooks`; OpenCode's Linux and macOS bootstrap runs the POSIX command.

## Acceptance criteria

- **AC-1:** A native SessionStart entry generated by #412 runs through OpenCode on Linux and macOS with a protocol-compatible executable fixture, and its `additionalContext` reaches the session. The current `toolu` binary's native diagnostic reaches the session; until #431 ports statusline, a generated-native statusline entry uses #412's Bun fallback and publishes its wrapper.
- **AC-2:** With the native entry and `TOOLU_BIN` pointing to a missing path, OpenCode starts and includes both #412 install commands in the session context message.
- **AC-3:** Generated Bun and native entries pass repository launcher checks, while a hand-edited command fails the appropriate check.
- **AC-4:** Switching one `hooks.json` entry to native in a fixture keeps its coverage inventory ID, changes `hostMechanism` to `native`, and passes the coverage check with updated fixture inventory and matrix.
- **AC-5:** Unknown lifecycle command forms remain reported, and native entries retain the existing environment, timeout, ledger, output, and cancellation behavior.

## Documentation impact

Update `docs/opencode.md` for native lifecycle entry support and `docs/gate-coverage-matrix.md` wording about Bun versus native. Keep generated OpenCode resource copies synchronized where those documents are mirrored.

## Open Questions

None. The missing-binary case uses #412's explicit `TOOLU_BIN` override to exercise the install message without changing the transitional Bun fallback.
