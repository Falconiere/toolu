# Dashboard worker logs — local evidence

2026-10-27, branch `feat/696-dashboard-worker-logs-follow-a`, PR #718.

- Real managed shell processes in `jobs_test` and `http_logs_test` streamed stdout and stderr into per-lease files. The tests observed growth before exit, returned `Output` unchanged, a retained 8 MiB tail, monotonic logical cursors, and `running` to `done` after lease release. The local HTTP listener returned 401 without the token, 200 with it, redacted the canary in both list and detail, and returned 404 for a foreign issue and foreign log ID.
- The real Claude Code task directory observed for the existing #655 worker under `/private/tmp/claude-501/<worktree-slug>/<session>/tasks` contained regular `.output` files and a symlinked `.output` pointing to a subagent transcript. The discovery test recreated those file types in a temporary worker slug and confirmed only the regular file appeared, with its first line as label and its text available at offset 0. No private task output was copied into this evidence.
- The #655 worktree had been removed before the end-to-end probe, so its remaining temporary task files were correctly excluded. A local listener then used the existing #656 Claude Code worktree. Its list returned at least 10 regular task outputs, excluded the symlinked task ID, and a selected detail read returned HTTP 200 with a positive next cursor. The probe asserted metadata and status only; it did not print or save task text.
- A checkout-built engine fixture served a real managed job log to Chromium at a loopback listener. The browser opened a token URL, which became `#issue=local-658` after token storage. The accessibility tree showed Screen and Logs tabs. Selecting Logs showed `JOB · ✓ DONE` and `probe log`. Over 2.2 seconds the browser recorded two list requests and two cursor detail requests, all 200. Selecting Screen and waiting 2.2 seconds produced no log requests. Closing the drawer and waiting 1.5 seconds also produced no log requests.
- A second checkout-built listener served a 70 KB output from a real managed shell job. Chromium opened the token URL, selected Logs and showed the done job. Its log view began at scroll position 81,029 of 81,029. Focusing the log and pressing Home moved it to 0 and exposed Jump; it stayed at 0 after 2.2 seconds of polling. Clicking Jump returned to 81,029 and hid the button. Switching Chromium to another tab produced `hidden` then `visible` events 2.73 seconds apart; the browser resource timeline contained no log requests in the interior of that hidden interval and resumed requests on return. The temporary listener and browser were closed, and its source-only fixture was removed.
- After rebasing over the dashboard control UI, a fresh checkout-built listener confirmed the shared token flow. Chromium consumed the token fragment, displayed the unlocked control, selected Logs and loaded 30,720 visible log characters. Locking control cleared session storage, hid the log text and showed the token-required note; a subsequent 2.2-second interval captured no log requests. Reopening the token URL through a hash change restored the token, kept Logs selected and resumed the log read with 65,536 visible characters. The temporary listener and browser were closed, and its source-only fixture was removed.
- The web gate and generated API reference check passed locally before the full gate. Full gate and final review results are recorded in the PR delivery notes.
