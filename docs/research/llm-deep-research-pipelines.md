# Deep-Research Pipelines for LLM Agents (2026): Research Report

> Date: 2026-08-10 · Questions: 5 approved · Scope: how state-of-the-art LLM agent systems implement deep-research pipelines in 2025–2026 — architectures, question targeting, verification, multi-agent trade-offs, and report conventions — to benchmark toolu's `deep-research` skill against the field.

## TL;DR

- Every major deep-research product converges on the same skeleton — plan → search/read → iterate → synthesize — but splits on orchestration: OpenAI trains one end-to-end reasoning model, Anthropic runs an orchestrator with 3–5 parallel subagents, Gemini runs an async planner loop, and Perplexity now compiles research into code that executes thousands of parallel retrieval steps.
- Up-front question clarification is now a first-class pipeline stage with direct evidence behind it: Gemini's API ships a literal `collaborative_planning` approval gate, OpenAI inserts a clarifier model before research, and the IDRBench benchmark finds user interaction "consistently improves research quality and robustness" — validating toolu's approve-before-research gate.
- Citation trust is the field's open wound: frontier agents keep link validity above 94% while only 39–77% of claims are actually supported by their cited source, and accuracy *drops* (~42%) as retrieval scales — so verification must check claim→source support, not link liveness.
- Multi-agent fan-out pays only on parallelizable, breadth-first work: Anthropic measured a 90.2% win over single-agent at ~15× token cost, while Google's 180-configuration study shows centralized coordination gaining up to 80.9% on parallelizable tasks yet *degrading* sequential tasks 39–70% — team sizes cap out around 3–4 workers.
- Report conventions have settled: TL;DR-first inverted-pyramid structure, claim-adjacent inline citations resolving to one deduplicated bibliography, and reliability signaling done as per-claim evidence checks rather than link badges.

## What pipeline architectures do leading deep-research products use?

All four major systems share the plan → search → read → iterate → synthesize shape but differ sharply in orchestration. **OpenAI Deep Research** is a single frontier reasoning model (o3-derived, now gpt-5-class) trained end-to-end with RL to plan its own browsing trajectory, call search and Python tools, and backtrack — runs take tens of minutes, and the API exposes the full trace; OpenAI's own cookbook wraps a four-agent front end (triage → clarifier → instruction-writer → researcher) around that single research model rather than parallelizing the research itself. **Anthropic's Claude Research** is explicitly orchestrator–worker: an Opus-class lead plans (persisting the plan to memory to survive context truncation), spawns 3–5 Sonnet-class subagents in parallel — each itself parallelizing 3+ tool calls — loops on "enough evidence yet?", and hands the final report to a dedicated CitationAgent. **Gemini Deep Research** runs an explicit async Plan → Multi-source search → Iterate → Output loop with a planner deciding which subtasks run concurrently; runs routinely exceed synchronous timeouts, so the API requires background execution (`background=True`) and can survive client disconnects. **Perplexity** folded Deep Research into "Computer" with a 2026 "Search as Code" architecture: the model writes code that plans and executes thousands of parallel retrieval steps in a sandbox, deduping and filtering programmatically — the fastest system on its own DRACO benchmark (459.6s vs 592–1808s). The common levers across all four: separate cheap planning/routing from expensive execution, use parallel fan-out as the main latency lever, exit the loop on evidence sufficiency rather than a fixed step count, and run async once wall-clock exceeds minutes.

## How do these systems clarify and decompose the question with the user first?

"Clarify before research" is now a first-class stage, with varying gate strength. ChatGPT's Deep Research runs a three-step front end — an intermediate model (e.g. gpt-4.1) asks clarifying questions, rewrites the request into a detailed brief, then hands off — and surfaces an editable research plan; the raw API skips clarification by default, leaving it to developers. **Gemini has the strongest gate**: beyond the consumer app's editable plan, the API exposes a boolean `collaborative_planning` that returns a plan *instead of executing*, supports iteration via `previous_interaction_id`, and requires explicitly flipping the flag to approve and start — a machine-enforced approval gate, structurally the same design as toolu's `AskUserQuestion` gate. Claude Research bakes a conversational gate into its system prompt: up to three clarifying questions only when genuinely needed, and an explicit instruction to wait for the user's answer before invoking research. LangChain's `open_deep_research` reference architecture formalizes clarification as a graph node (`clarify_with_user`) with structured output routing to either a question or `write_research_brief`. Perplexity is the outlier, refining its plan internally rather than blocking on approval. The evidence side is direct: IDRBench (2026) evaluates seven deep-research agents autonomous-vs-interactive and finds interaction consistently improves quality and robustness; companion work finds 16–50% of benchmark questions are underspecified and that rewriting them into fully-specified variants improves QA performance — ambiguity, not capability, is the bottleneck — while LLMs left to defaults answer rather than ask, which is exactly why products hard-code the clarification stage.

## What verification and grounding techniques reduce hallucinated citations?

The headline 2025–2026 finding is that surface citation quality and factual grounding have decoupled: frontier deep-research agents keep link validity above 94% and topical relevance above 80%, yet only 39–77% of claims are factually supported by the cited source, and fact-check accuracy drops ~42% on average as search depth scales from 2 to 150 tool calls — more retrieval does not produce more accurate citations. URL fabrication is separately quantified: across 10 commercial LLMs/deep-research agents, 3–13% of cited URLs are outright hallucinated (no Wayback Machine record) and 5–18% don't resolve; wiring URL-liveness checking into an agentic self-correction loop cuts non-resolving citations 6–79×, to under 1%. The mitigation toolbox in use: structural claim→source binding (AST-parsed inline citations scored separately for link, relevance, and factual support), post-hoc re-crawling of cited pages to re-check claims against actual content (the approach toolu's verification wave implements), LLM-as-judge rubric scoring calibrated across judge models, multi-round audit-then-score adjudication, and conformal-prediction guards bounding the slip-through rate of unsupported citations. A meta-caveat the literature itself flags: "unsupported citation" rates are verifier-dependent — identical outputs score 3–18% unsupported depending on the checker, since verifiers agree on supported citations (0.90–0.96) but not on what to flag (0.27–0.30). Shipped products remain imperfect: DeepTRACE audits put citation accuracy at 40–68% for consumer generative search engines, and OpenAI's own system card concedes weak confidence calibration.

## Multi-agent versus single-agent research pipelines — when does fan-out pay?

Fan-out pays on breadth, taxes on depth. Anthropic's production numbers anchor the upside: an Opus-lead + Sonnet-subagent system beat single-agent Opus by 90.2% on an internal breadth-first research eval, with token spend explaining ~80% of performance variance — but multi-agent runs burn ~15× the tokens of a chat, so Anthropic scopes the pattern to high-value, parallelizable, context-exceeding tasks. Google Research's 180-configuration study (validated in Nature Machine Intelligence) draws the sharpest boundaries: centralized coordination lifted parallelizable tasks by up to 80.9% (⚠ corrected in verification from the researcher's "80.8%"; the gain belongs specifically to *centralized* coordination, not multi-agent designs generally), yet every multi-agent variant degraded sequential-planning tasks by 39–70%; uncoordinated agents amplify errors 17.2× versus 4.4× under centralized/verified coordination; gains saturate once a single-agent baseline exceeds ~45% accuracy; and useful team size caps around 3–4 agents as communication overhead scales super-linearly. The failure-mode literature (MAST taxonomy, NeurIPS 2025; error-cascade modeling) attributes most multi-agent failures to organizational design — inter-agent misalignment, task derailment, false consensus from one unverified claim propagating — not base-model weakness. Cognition's "Don't Build Multi-Agents" makes the single-agent case for tightly-coupled work: splitting loses context nuance between agents ("context isn't able to be shared thoroughly enough"), so linear agents with compaction beat fan-out on coding-like tasks. The field's converged decision rule matches toolu's design: fan out only for genuinely decomposable, breadth-first research questions, keep the team small, and coordinate centrally with verification.

## What citation and report-format conventions have emerged?

Two conventions have effectively standardized: claim-adjacent inline citations (numbered or hyperlinked markers next to the claim they support) resolving to a single consolidated, deduplicated end-of-report bibliography with continuous numbering — the schema evaluation frameworks (ReportBench, DeepResearch Bench's FACT, LiveResearchBench) also assume, because adjacency makes automated claim→source verification tractable; and TL;DR-first inverted-pyramid structure — a dense executive summary (context, 3–5 key findings, recommendation, primary caveat) rendered first, with methodology-first openings treated as an anti-pattern. The dominant defect class in production reports is citation *discipline*, not style: mismatched in-text/reference numbering, orphaned or duplicated bibliography entries, and double-counting a URL inline and in the list; LiveResearchBench documents these across vendors, and its authors patched one open-source system (their "Deerflow+" variant) with a validator enforcing one-to-one in-text↔reference mapping (⚠ verification narrowed the researcher's claim here: that validator is the paper's own one-off patch, not yet an industry-wide practice). Visible source-reliability grading has *not* shipped as a default convention anywhere major — confidence signaling lives in post-hoc evaluation rubrics (Deep-Research Eval's 1–5 source-reliability scale; 2026 proposals for per-claim progressive confidence estimation) — and the de facto style standard is increasingly set by academic rubric suites (RACE/FACT, ResearchRubrics, DEER) rather than any lab's style guide. Worth adopting for toolu reports: the two standardized conventions above (already in the skill's template), plus per-claim evidence-support checks over link-liveness badges — since link validity and factual support are proven to diverge.
